# Documentation Management Rules

When operating in this workspace, all agents must adhere to the following documentation conventions:

## 1. Document Categories
- **`docs/active_plans/`**: For currently active, ongoing development plans or roadmaps (e.g., `PLAN.md`).
- **`docs/ai_proposals/`**: For any analysis, code reviews, architectural suggestions, or product ideas generated by AI agents.
- **`docs/archive/`**: For completed plans, implemented designs, deprecated features, and past summaries.

## 2. Naming Conventions & Dates
- **Dates are strictly required** for all new historical, review, and proposal documents.
- Use the format `YYYY-MM-DD_Subject.md` (e.g., `2026-06-22_Product_Improvement.md`).
- Put the date at the top of the markdown file content as well.
- Core active documents (like `docs/active_plans/PLAN.md`) do not require a date in their filename, but should be updated with a timestamp inside when changed.

## 3. Workflow for Agents
- **When creating reviews or proposals**: Put them in `docs/ai_proposals/` with a dated filename.
- **When finishing a plan or task**: If the entire plan document is completed, move it to `docs/archive/` and ensure the filename has a date prefix.
