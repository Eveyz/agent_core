# 2026-07-07

## Added `prompts` table between sessions and messages

**Why:** The old flat `sessions → session_messages` design had no explicit turn/prompt boundaries. Prompt boundaries were inferred by scanning `role == User`, and there was no place to store per-prompt metadata (token usage, model, timing, etc.).

**New schema:**
```
sessions (1) → prompts (N) → session_messages (N)
```
- `prompts` table: id, session_id, turn_index, user_message, model, status, token_usage, started_at, ended_at, created_at
- `session_messages` now has `prompt_id TEXT NOT NULL DEFAULT ''` 
- `sessions` now has `prompt_count INTEGER DEFAULT 0`
- `SessionMeta` now has `prompt_count: u32` field

**Changes:**
- `core/src/memory/storage.rs`: Added `prompts` table schema + migrations
- `core/src/session.rs`: Added `Prompt` struct, `split_into_prompts()` method, updated `save_full()` to split messages into prompts automatically, updated `resume()` to load prompts (with legacy fallback for old data), updated `delete()` to clean up prompts
- `core/src/lib.rs`: Exported `Prompt`
- `app/src-tauri/src/lib.rs`: Added `prompts` to `FrontendSession`
- `app/src/features/project/projectSlice.ts`: Added `FrontendPrompt` type, `prompt_id` to `FrontendMessage`, `prompts` to `ResumeSessionResult`

**Test results:** 19/25 session tests pass. The 6 failing tests (cascading_delete, count, purge_archived, summary, tags, unarchive) are pre-existing FTS5 trigger/OOM issues unrelated to this change.

## Added transactions to save_full and delete

- `save_full()`: wrapped in `tx = db.transaction()?` → `tx.commit()?`. Crash mid-save = auto rollback.
- `delete()`: fixed mutex deadlock risk — child queries now drop the lock before recursing. Parent deletion in a single transaction. Filesystem cleanup happens after commit (best-effort).

## Zombie task recovery: prompt lifecycle split + startup repair

**Problem:** When app crashes / loses power / gets killed by cargo watch, long-running tasks (Runs, workflow runs) leave no trace of their interrupted state. The frontend shows "Working..." forever.

**Solution (based on Gemini proposal, adapted for agent_core's actual architecture):**

### Prompt lifecycle split (`core/src/session.rs`):

- **`create_prompt(session_id, user_message, model) -> (prompt_id, turn_index)`**: Creates prompt with status='running' and `started_at` set. Called at the START of a Run.
- **`finish_prompt(prompt_id, status, token_usage)`**: Updates prompt status to 'completed'/'cancelled'/'failed' and sets `ended_at`. Called on terminal Run events.
- **`repair_zombie_prompts()`**: `UPDATE prompts SET status='interrupted', ended_at=? WHERE status='running'`. Called at app startup.

### Frontend event loop integration (`app/src-tauri/src/lib.rs`):

- **`send_message()`**: After run creation but before start, calls `create_prompt` to create a prompt with 'running' status. The `prompt_id` is passed to the event forwarding task. When a terminal event (RunCompleted/RunCancelled/RunFailed) is received, calls `finish_prompt` to update the prompt status.
- **`setup()` startup repair**: Before app initialization completes, executes `repair_zombie_prompts` (prompts) and equivalent SQL for `workflow_runs` table. Both tables have any 'running' entries repaired to 'interrupted'.

### Save-preserving behavior (`save_full`):

- No longer DELETEs prompts before re-inserting them during session save.
- Uses UPSERT pattern: finds existing prompt by (session_id, turn_index), updates non-lifecycle fields (user_message, model) while preserving status + timestamps.
- New prompts (legacy data / fresh sessions without pre-created prompts) are still INSERTed with 'completed' status.

### Key insight:

- The `prompts` table was the right granularity (1:1 with runs) rather than sessions (1:N) or event logs (file-based).
- Workflow runs in SQLite were already persisted with 'running' status — adding the repair SQL closes that gap.
- Gemini's 方案二 (Drop guard) was already partially implemented in `Run::Drop` — no changes needed there.
- Build verified: `cargo build` succeeds with zero new warnings.

### Frontend changes:

- **`types.ts`**: Added `interrupted?: boolean` to `ChatEntry`.
- **`chatSlice.ts`**: `resumeSession.fulfilled` now reads `prompts` from backend, builds `promptStatusByTurn` map, and sets `interrupted: true` on entries whose prompt has status='interrupted'.
- **`TurnFooter.tsx`**: When `entry.interrupted && !entry.endTime`, shows ⚠️ "Interrupted" with warning color instead of 🔄 "Working..." spinner.
- **`chat.css`**: Added `.turn-footer-interrupted` styles with `var(--warning)` color.
