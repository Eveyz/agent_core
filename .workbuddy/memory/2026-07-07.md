# 2026-07-07

## Added `prompts` table between sessions and messages

**Why:** The old flat `sessions → session_messages` design had no explicit turn/prompt boundaries. Prompt boundaries were inferred by scanning `role == User`, and there was no place to store per-prompt metadata (token usage, model, timing, etc.).

**New schema:**
```
sessions (1) → prompts (N) → session_messages (N)
```
- `prompts` table: id, session_id, turn_index, user_message, model, status, token_usage, started_at, ended_at, created_at
- `session_messages` now has `prompt_id TEXT NOT NULL DEFAULT ''` 
- `sessions` now has `prompt_count INTEGER DEFAULT 0`
- `SessionMeta` now has `prompt_count: u32` field

**Changes:**
- `core/src/memory/storage.rs`: Added `prompts` table schema + migrations
- `core/src/session.rs`: Added `Prompt` struct, `split_into_prompts()` method, updated `save_full()` to split messages into prompts automatically, updated `resume()` to load prompts (with legacy fallback for old data), updated `delete()` to clean up prompts
- `core/src/lib.rs`: Exported `Prompt`
- `app/src-tauri/src/lib.rs`: Added `prompts` to `FrontendSession`
- `app/src/features/project/projectSlice.ts`: Added `FrontendPrompt` type, `prompt_id` to `FrontendMessage`, `prompts` to `ResumeSessionResult`

**Test results:** 19/25 session tests pass. The 6 failing tests (cascading_delete, count, purge_archived, summary, tags, unarchive) are pre-existing FTS5 trigger/OOM issues unrelated to this change.
