## std::fs → tokio::fs migration (24 calls in async context)

将 4 个核心文件中 24 处 `std::fs` 调用迁移至 `tokio::fs`，消除 async 运行时中的阻塞 I/O：
- `memory/reflection.rs`: 2 calls (read_to_string, write) — 已 async fn，直接加 .await
- `reflector/mod.rs`: 4 calls — load_trace/load_event_log/apply/write_skill 改为 async fn，同步更新 comprehensive/mod.rs 和 runtime/manager.rs 的调用方
- `runtime/run.rs`: 8 calls — refresh_context_segments 和 write_session_memory 改为 async fn
- `tools/grep.rs`: 1 call — read_dir → tokio::fs::read_dir (next_entry 模式)

注：tools/edit.rs、tools/read_file.rs、tools/write_file.rs 在本次修改前已经使用 tokio::fs。

## Subagent 消息持久化 & 上下文窗口优化

**问题**：subagent 的结果在下一个 prompt 会丢失，原因有三层：
1. `max_context_tokens: 32000` 硬编码——subagent 自己的窗口太小
2. `SUBAGENT_RESULT_MAX_CHARS: 64000` 上限太低
3. `_messages`（subagent 完整对话）被丢弃，只有摘要返回父上下文

**改动（4 个文件）**：

1. **`core/src/tools/subagent.rs`** — `spawn_single()` 中 `max_context_tokens: 32000` → `model_config.max_context_tokens`，继承父模型窗口
2. **`core/src/tools/subagent.rs`** — 新增 `persist_subagent_messages()` 函数，将 subagent 完整消息写入 `~/.agverse/subagents/{agentId}_{ts}.messages.json`；`execute_with_stream` 返回摘要 + 文件路径（父上下文保持小而稳定 → cache hit 高）
3. **`core/src/session.rs`** — 新增 `save_subagent_with_messages()` 方法，SQLite 保存完整对话而非仅 2 条摘要
4. **`core/src/hygiene/policy.rs`** — `SUBAGENT_RESULT_MAX_CHARS`: 64K → 256K；`ACTIVE_READ_MAX_CHARS`: 24K → 128K
5. **`core/src/subagent/mod.rs`** — `SubagentConfig::default()` 中 `max_context_tokens: 32000` → 128000

编译通过（`runtime/manager.rs` 的 reflector 缺失 `.await` 是预先存在的无关错误）。
