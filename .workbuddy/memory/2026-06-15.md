## 修复：切换模型后请求仍然打到旧 URL

### 根因
前端切换模型只更新了 Redux 状态和 config.toml 文件，但后端的 Agent 在启动时就创建好了，内存中的 Config 和 Client 不会自动更新。所以切换模型后 send_message 还是用的启动时的旧模型 URL。

### 修复
- `core/src/agent.rs`: Agent 的 `config` 字段从 pub(crate) 改为 pub，允许外部更新
- `app/src-tauri/src/lib.rs`: 新增 `switch_model` Tauri command，先重新加载 config.toml 更新 agent.config，再调用 agent.switch_model() 切换当前模型和 client
- `ModelSelector.tsx`: handleSelect 中增加 `await invoke('switch_model', { name: key })` 调用

现在切换模型时：
1. 前端 → saveConfig 保存 config.toml
2. 前端 → switch_model 通知后端
3. 后端 → 重新读取 config.toml → 更新 agent.config → switch_model 切换 client
4. 下次发消息时使用正确的 base_url 和 api_key

- TypeScript (`tsc --noEmit`) 通过
- Rust (`cargo check`) 通过

## 修复 streaming "error decoding response body"

### 根因
`reqwest` 默认会自动解压 gzip/deflate/brotli 响应体。部分 provider（如 volces/火山引擎）返回的 Content-Encoding 与 body 不匹配，导致 `resp.chunk()` 在解压时失败，报 "error decoding response body"。

### 修复 (core/src/client/mod.rs)
`OpenAIClient::new()` 中 reqwest builder 添加 `.no_gzip().no_deflate().no_brotli()`，禁用自动解压。server 看不到 `Accept-Encoding` header 就会返回未压缩数据，避免 mid-stream 解压失败。
