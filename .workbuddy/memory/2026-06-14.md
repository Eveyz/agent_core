## Settings 崩溃修复

### 修复 1: `Cannot read properties of undefined (reading 'length')`
- 根因：Rust 后端对空数组使用了 `#[serde(skip_serializing_if = "Vec::is_empty")]`，导致前端访问 `config.permissions.rules.length` 时值为 `undefined`
- 修复：`settingsSlice.ts` 的 `normalizeConfig` 为所有可能缺失的字段补上默认值

### 修复 2: `Cannot read properties of null (reading 'toLocaleString')`
- 根因：`normalizeConfig` 虽然补了顶层默认值，但 `raw.models` 中的单个模型字段（如 `max_context_tokens`）仍可能为 `null/undefined`，ProviderTab 直接调用 `.toLocaleString()` 导致崩溃
- 修复：
  - `settingsSlice.ts`: 新增 `normalizeModel()` 和 `normalizeMemory()`，对每个模型/内存配置逐项填充默认值
  - `ProviderTab.tsx`: 所有 `.toLocaleString()` 调用改为 `(value ?? 0).toLocaleString()`，`max_iterations` 和 `request_timeout_secs` 也加了 fallback
  - `MemoryTab.tsx`: `default_block_max_chars.toLocaleString()` 同样加了 fallback

## Provider Tab 重新设计：Provider-Model 层级结构

将 Provider Tab 改为"一个 Provider 下多个 Model"的层级编辑界面。

### 逻辑改动
- **Provider 分组**：按 `base_url + api_key` 自动分组，相同 endpoint 的模型归为一个 Provider Card
- **ProviderForm 组件**：
  - 顶部：Base URL、API Key、通用配置（temperature、max_tokens、timeout、iterations、react、system_prompt）
  - 下方 **Models section**：表格形式，每行有 Display Name（config key）和 Model ID
  - 每行右侧有删除 icon，最后一行不可删除（至少保留一个 model）
  - 下方有 "+ Add Model" 按钮添加新行
- **编辑逻辑**：点击 Edit 时，自动找到同 Provider（同 base_url + api_key）下的所有模型，在表单中一并展示和编辑
- **保存逻辑**：先删除原 Provider 下的所有旧模型，再为每行生成新的 ModelConfig
- **卡片展示**：每个 Provider Card 展示 base_url、模型数量、通用配置摘要，以及下面的模型子列表（含 default 标记）

### 样式改动 (App.css)
- 新增 `.models-section`、`.models-table`、`.models-table-row`、`.model-row-delete`、`.btn-add-model`、`.provider-models-list` 等样式
