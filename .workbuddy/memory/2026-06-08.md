# 2026-06-08 TUI 优化：pulldown-cmark + syntect

## 背景

ratatui TUI 的手写 markdown 解析和代码高亮很不好用，讨论后决定方案 A：在 ratatui 基础上优化，不切 TypeScript。

## 完成的改动

### 1. Markdown 解析：手写 → pulldown-cmark

- `render.rs` 中删除了约 500 行手写解析代码（`markdown_to_lines`, `parse_inline_spans`, `parse_markdown_table`, `split_table_row`, `is_table_separator`, `render_code_block`, `highlight_code_line`, `flush_code_token`, `is_code_keyword`, `normalize_language`）
- 替换为 `markdown_to_lines()` 使用 `pulldown_cmark::Parser` 事件流驱动
- 支持：Heading (h1-h3)、Bold/Italic/Strikethrough、Inline code、Blockquote、有序/无序列表、水平线、表格(passthrough)

### 2. 代码高亮：手写关键词 → syntect

- 使用 `syntect::easy::HighlightLines` + Sublime Text 语法定义
- `SyntaxSet` 和 Theme（base16-ocean.dark）通过 `LazyLock` 只加载一次
- `find_syntax()` 映射 30+ 语言名称到 syntect token
- `syntect_color_to_ratatui()` 转换颜色

### 3. 输入框增强

- Ctrl+A/E：行首/行尾
- Ctrl+K/U：删除到行尾/行首
- Ctrl+W：删除前一个词
- Ctrl+Left/Right：按词移动
- Ctrl+Backspace/Delete：删除词

### 4. 放弃了 tui-textarea

- tui-textarea 0.7 依赖 crossterm 0.28，我们用的 ratatui 0.30 需要 crossterm 0.29
- 保留手动输入管理 + 快捷键增强方案更务实

## 依赖变更

- 新增：`pulldown-cmark = "0.13"`, `syntect = { version = "5", features = ["default-syntaxes", "default-themes"] }`

## 测试结果

- 196 tests (185 unit + 11 integration): **all passed**
- cargo check: zero warnings, zero errors

## Bug 修复：TUI 审批卡死

**问题**：输完命令后 agent 请求审批 `run_command`，UI 显示 "APPROVAL" 但卡住不响应。

**根因**：agent 权限检查返回 `Ask` 时创建 oneshot 通道并阻塞等待。TUI 的 `state.rs` 虽然显示了审批通知，但**从未发送审批回应**，agent 永久阻塞。

**修复**：
- `state.rs`：`ApprovalRequired` 事件保存 `prompt_id` 到 `state.pending_approval_id`
- `mod.rs`：事件循环中调用 `agent.approve(prompt_id, AllowSession)` 自动批准
- 与 CLI 模式的 auto-approve 行为一致（`main.rs` line 1411-1416）

## Bug 修复：tokio mutex 死锁 + 子 agent approvals 隔离

**问题**：修复审批后仍然卡在 tool 调用。两个根因：

1. **死锁**：`mod.rs` 主循环调 `agent.lock().await` 等锁，而 spawn 任务持锁等 oneshot 回应 → 互相等死
2. **子 agent approvals 隔离**：子 agent 有独立的 `pending_approvals` Arc，TUI state 持有的父 Arc 找不到子 agent 的 sender

**修复**：
- `agent.rs`：`AgentBuilder` 新增 `pending_approvals_override` 和 `with_pending_approvals()`，父子共享一个 Arc
- `state.rs`：`ApprovalRequired` 直接通过共享 Arc 发 `AllowSession`，不经过 tokio mutex
- `mod.rs`：启动时传 `agent.pending_approvals_clone()` 给 state，删掉死锁代码

## UI 改进：边框改背景色 + 流式输出 scroll 修复

**问题 1**：Tool/Code/Subagent 块用 ASCII 边框（╭╮╰╯│─），终端宽度变化时右边框对不齐，截图显示断裂。

**修复**：全部改成背景色填充风格（和 User block 一致）
- `render_tool_block`：CODE_BG 背景 + 顶部 `⚙ name` 标签 + 虚线分隔
- `render_subagent_block`：CODE_BG 背景 + 顶部 `⚡ subagent: id` 标签
- `render_syntect_block`：去掉 `│ ` 左边框和 `╭─╮╰╯` 外框，改为顶部标签 + 纯代码行

**问题 2**：流式输出时 scroll 失效——新内容一来就把视图推回底部。

**根因**：`scroll` 语义是"从底部往上偏移"。内容增长时 `max_scroll` 增大，`scroll = max_scroll - state.scroll` 也增大 → 视图被推到底部。

**修复**：
- `AppState` 加 `last_content_lines: usize` 记录上次内容高度
- `render_conversation` 接受 `&mut AppState`，渲染前检查：若 `max_scroll > last_content_lines` 且 `state.scroll > 0`（用户手动滚动了），将 `state.scroll` 增加相同量，保持视图位置不变
- `render` / `mod.rs` 签名改为 `&mut AppState`

196 tests passed.

## UI 细节修复：双重⚠、icon间距、黑色空行

**问题 1**：Approval 通知显示 `⚠ [⚠ APPROVAL] ...`，两个 warning sign。

**修复**：`state.rs` 中 `[⚠ APPROVAL]` → `[APPROVAL]`，Notice block 的 prefix `⚠` 保留，总共只有一个。

**问题 2**：`⚙run_command` icon 和文字贴在一起。

**修复**：`render_tool_block` label `" ⚙ {} "` → `"  ⚙  {}  "`，`render_subagent_block` label `" ⚡ subagent: {} "` → `"  ⚡  subagent: {}  "`，增加间距。

**问题 3**：Tool/Subagent 块底部有一行黑色空行。

**修复**：top/bottom padding 从 `"    "`（4 个空格）改为 `" ".repeat(width.saturating_sub(pad.width()))`（填充整行宽度），消除终端默认背景色露出。

## UI 改进：block 间距 + scroll 逻辑简化

**问题 1**：不同 block（Approval/Thought/Tool）之间没有空行，挤在一起。

**修复**：
- 去掉 `render_turn_block` 中 Thought 自己的尾部空行（避免双重空行）
- `render_entry` 和 `render_conversation` 的 streaming blocks：consecutive blocks 之间统一插入 `Line::raw("")`

**问题 2**：scroll 卡顿——内容增长时视图位置不稳定。

**根因**：`last_content_lines` 补偿逻辑在内容从 `max_scroll=0` 第一次增长时产生巨大增量，导致 scroll 位置跳跃。

**修复**：
- 移除 `last_content_lines` 字段和补偿逻辑
- 每帧渲染后 `state.scroll = state.scroll.min(max_scroll)`，防止 scroll 超过实际范围
- 当 `state.scroll > 0` 时，状态栏显示黄色提示 `⬆ scroll paused — press End to resume`
- 行为：默认自动跟到底部；按 Up/PageUp 后停在当前位置；按 End 恢复自动跟随

196 tests passed.

## UI 修复：Tool/Subagent 块右边不齐

**问题**：Tool/Subagent 块右侧背景没有填满，出现锯齿/缺口。

**根因**：`inner_width = width.saturating_sub(8)` 硬编码减 8，但实际 padding 只有 `pad.width() + 4`（pad + 左右各两个空格）。顶层 block（pad=""）时内容宽度 = width - 4，但 inner_width = width - 8，右侧缺 4 格。

**修复**：`render_tool_block` 和 `render_subagent_block` 中 `inner_width` 改为 `width.saturating_sub(4 + pad.width())`。build passed。

## UI 改进：markdown 渲染增强

**问题**：heading、paragraph、list 之间没有空行，内容挤在一起；heading 只有加粗没有颜色区分。

**修复**：
- `markdown_to_lines`：paragraph 结束后加空行，list 结束后加空行
- heading 按级别着色：h1 蓝、h2 青、h3 绿、h4 黄、h5 洋红、h6 灰
- 新增 `heading_color()` 函数

## UI 改进：LLM 等待 loading indicator

**问题**：用户输入问题到模型输出第一个 token 之间有 2-5 秒空白期，没有任何反馈。

**修复**：
- `AppState` 加 `is_agent_running()` pub 方法
- `render_conversation`：当 `is_agent_running() && streaming blocks 为空` 时，在对话区末尾显示 `⏳ Thinking...`
- 第一个实质事件（Thinking/Text/Tool/Subagent）到达时 streaming.blocks 不为空 → indicator 自动消失
- 适用于所有场景：初始 thinking、tool calling、subagent 启动

build passed。

## 功能：TUI 斜杠命令系统 + /models new + Tab 自动补全

**问题**：TUI 输入框直接发送给 agent，没有命令解析；无法注册新模型；无自动补全。

**实现**：

### 命令系统
- `state.rs`：新增 `CommandMode` 枚举（None / ModelNewProvider / ModelNewBaseUrl / ModelNewApiKey / ModelNewModelName），`pending_command` 字段和 `handle_command()`、`take_pending_command()` 方法
- `input.rs`：Enter 键拦截 `/` 前缀，调度到 `state.handle_command()`；Esc 取消命令模式
- `mod.rs`：`process_command()` 函数处理需要 agent 访问的命令（list_models、switch_model、clear、register_model）

### /models new 多步输入
- 输入 `/models new` → 命令模式启动 → input bar 显示黄色提示
- 四步：Provider name → Base URL → API Key → Model name
- 完成后写入 config.toml（追加 `[models.xxx]` 节）+ agent 内存注册

### Tab 自动补全
- `input.rs`：Tab 键匹配 `/` 开头的命令（/help, /quit, /models, /models new, /model, /clear, /new）
- 前缀匹配到第一个候选项，自动补全

### 其他命令
- `/help`：显示帮助文本
- `/models`：列出已注册模型（* 标记当前）
- `/model <name>`：切换模型
- `/quit` / `/exit`：退出 TUI
- `/clear` / `/new`：清空对话

### 后端
- `config.rs`：`Config::add_model()` 方法
- `agent.rs`：`Agent::register_model()` + `model_config()` 方法

build passed。
