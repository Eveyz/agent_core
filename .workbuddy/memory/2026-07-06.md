# 2026-07-06

## Fixed: Model settings (context token, reasoning, thinking) lost after restart

**Root cause**: Frontend data normalization in `normalizeProviderModel()` (`settingsSlice.ts`) stripped `max_context_tokens`, `reasoning_effort`, `thinking_enabled` fields when converting raw config from Rust backend to Redux state. Subsequent saves wrote incomplete config back to `~/.agverse/config.toml`.

**Changes made** (4 fixes):
1. `app/src/features/settings/settingsSlice.ts` — `normalizeProviderModel()`: added `max_context_tokens`, `reasoning_effort`, `thinking_enabled` to the return object
2. `app/src/components/settings/ProviderTab.tsx` — `modelRowToEntry()`: added missing `temperature` field
3. `app/src/components/settings/ProviderTab.tsx` — form init (`useEffect`): added `temperature` to model row mapping
4. `app/src/components/settings/ProviderTab.tsx` — `handleSave()`: replaced hardcoded provider-level values (`max_context_tokens: 32768`, `temperature: undefined`, `max_tokens: undefined`) with original config values when editing existing providers

## Fixed: NVIDIA API thinking/reasoning_effort parameter format (`chat_template_kwargs`)

**Root cause**: `build_request_body()` in `client/mod.rs` put `thinking` and `reasoning_effort` at top level (OpenAI format), but NVIDIA requires them inside `chat_template_kwargs`. Added `use_chat_template_kwargs: bool` config option per-model.

**Changes**: `config.rs` (structs + rebuild), `client/mod.rs` (conditional body), frontend types + ProviderTab UI (NVIDIA checkbox column).

## Fixed: Rate limit (429) retry mechanism — was only 3 retries with short backoff

**Root cause**: `send_with_retry()` had hardcoded `max_retries = 3` for all errors, with max 10s backoff — useless for 429 rate limits that need minutes.

**Changes**: Separated 429 handling from 5xx/network. 429 now uses configurable `rate_limit_retries` (default 20) and exponential backoff from `rate_limit_retry_delay_secs` (default 60s, cap at 1h). Respects `Retry-After` header. 5xx/network stays at 3 retries with exponential backoff.

**Config fields**: `ProviderModelEntry` (per-model override), `ProviderConfig` (provider default), `ModelConfig` (runtime). Added to frontend types + ProviderTab init/persist.

**UI messages**: Added `status_cb` callback to `OpenAIClient` — wired in `Run::new()` to emit `RunEvent::Error { message }` when retrying 429, so frontend shows "429 rate limited, retrying in 60s (attempt 1/20)" in the chat as error blocks. Refactored 429 retry to exponential backoff.
