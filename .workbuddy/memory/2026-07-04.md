## webfetch.rs Anti-Detection Upgrade (Tier 1 + 2)

Rewrote `core/src/tools/webfetch.rs` with structural improvements:

- **UA profiles**: 8 weighted profiles (Chrome/Firefox/Safari desktop + mobile) with matching Client Hints (sec-ch-ua / sec-ch-ua-mobile / sec-ch-ua-platform). Chrome desktop ~70% weighted.
- **Header completeness**: Added Cache-Control, Pragma, DNT, Connection, Accept-Encoding, Sec-Fetch-User headers. Browser-like Accept with signed-exchange.
- **Cookie jar**: `reqwest::cookie::Jar` (Arc-shared) — persistent session cookies across requests on same domain.
- **Per-domain rate limiter**: 2-5s random delay between requests to same domain, with jitter.
- **Redirect chain tracking**: Final URL logged; explicit redirect info in output.
- **Meta extraction**: New `extract_meta()` — extracts title/description/og:tags from raw HTML without full parser.
- **Struct conversion**: `WebFetchTool` from unit struct → struct with state (cookie_jar + rate_limiter). Added `new()` / `Default`.
- **Dependency**: Added `cookies` feature to reqwest 0.12.
- **Updated call sites**: `mod.rs` lines 101, 278 now use `WebFetchTool::new()`.

Compiles clean, zero new warnings.

## #1 Critical Fix: Agent/Run Code Duplication Eliminated

Completed migration to eliminate ~1500 lines of duplicated run logic between legacy `Agent` and `Run`:

### Changes Summary

| File | Before | After | Delta |
|------|--------|-------|-------|
| `core/src/agent/mod.rs` | 1722 | 1089 | **-633** |
| `core/src/runtime/run.rs` | 1674 | 1677 | +3 |
| `core/src/runtime/brain.rs` | 515 | 520 | +5 |
| `core/src/runtime/manager.rs` | 685 | 690 | +5 |
| `core/src/agent/executor.rs` | ~475 | 482 | +7 |
| `core/src/subagent/mod.rs` | ~600 | 608 | +8 |

### Architecture Changes

1. **Agent now delegates to RunManager/Run**: `run_with_events()` creates a Run internally, subscribes to events via broadcast channel, translates `RunEvent` → `AgentEvent` via existing `to_agent_event()`, syncs context back on completion.

2. **Deleted from Agent**: `run_loop()`, `run_turn()`, `model_turn()`, `collect_stream()`, `try_recover()`, `force_compact()`, `maybe_compact()`, `refresh_context_segments()`, `maybe_consolidate()`, `build_iteration_limit_summary()`.

3. **Shared hook_registry**: Brain now has `hook_registry: Arc<Mutex<HookRegistry>>` shared with Agent. Runs use it directly. `ToolOrchestrator` updated to `Arc<Mutex<HookRegistry>>`.

4. **Context snapshot refresh**: Run::run() now calls `refresh_context_snapshot()` before terminal events, ensuring Agent wrapper gets final context.

5. **Added `runs_mut()` to RunManager** for Agent to retrieve RunHandles.

6. **Subagent updated** to use `Arc<Mutex<HookRegistry>>` for orchestrator compatibility.

### Preserved
- All public accessor methods (config, registry, memory, model switching, etc.)
- `build_messages()` — simplified for test compatibility
- `build_danger_map()` — still used for context initialization
- CLI/TUI code unchanged (still uses `Agent::run_with_events()` which now delegates internally)

### Known Limitations
- Tools registered post-build via `tool_registry_mut()` on Agent do NOT propagate to Run's tool registry. CLI doesn't use this path, so no impact currently.
- Stage/TurnOutcome/RecoveryOutcome enums removed from Agent (Run has its own copies).
