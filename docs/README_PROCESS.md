# Documentation & Decision Lifecycle Process (DDLP)

> Version: 1.0 | Last Updated: 2026-06-24

## 1. 设计哲学

- **状态驱动**：每份文档都有明确的生命周期状态，不是写完就扔
- **模板先行**：同类文档用统一模板，降低认知负担
- **可追溯**：任何设计决策都能通过文档 ID 反向查到依据
- **人机协作规范**：AI 产出和人类产出的边界、审批流程清晰

---

## 2. 文档类型体系

| 类型 | 前缀 | 用途 | 作者 | 审批 |
|------|------|------|------|------|
| **ADR** | `ADR-NNNN` | Architecture Decision Record，记录架构/设计决策 | 人类/AI | 人类 |
| **RFC** | `RFC-NNNN` | Request for Comments，重大功能/变更的提案 | 人类/AI | 人类 |
| **PLAN** | `PLAN-NNNN` | 开发计划/路线图，可跨多个版本 | 人类 | 人类 |
| **RUN** | `RUN-NNNN` | Runbook，操作手册（部署、故障恢复等） | 人类/AI | 人类 |
| **POST** | `POST-NNNN` | Post-mortem，事后复盘/故障分析 | 人类 | 人类 |
| **AI-NOTE** | `AI-NOTE-NNNN` | AI 分析、代码审查、建议（非决策性） | AI | 无需 |
| **META** | `META-NNNN` | 流程/规范本身的变更 | 人类 | 人类 |

> 编号全局递增，从 0001 开始。编号即文档 ID，永不复用。

## 4. 文档生命周期状态机

```
                    ┌─────────────┐
        ┌──────────►│   Draft     │◄────────┐
        │           │   (草稿)     │         │
        │           └──────┬──────┘         │
        │                  │                 │
        │           ┌──────▼──────┐         │
   [作者撤回]      │   Proposed  │    [修改]
        │           │  (已提出)   │         │
        │           └──────┬──────┘         │
        │                  │                 │
        │           ┌──────▼──────┐         │
        └───────────┤  In-Review  │─────────┘
                    │  (审核中)    │
                    └──────┬──────┘
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
     ┌─────────┐     ┌─────────┐     ┌─────────┐
     │ Accepted│     │ Rejected│     │Superseded│
     │ (已接受) │     │ (已拒绝) │     │(已取代)  │
     └────┬────┘     └────┬────┘     └────┬────┘
          │               │               │
          ▼               ▼               ▼
    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │Implemented│    │  Trash   │    │  Trash   │
    │ (已实施)   │    │ (废弃池)  │    │ (废弃池)  │
    └────┬─────┘    └──────────┘    └──────────┘
         │
         ▼
    ┌──────────┐
    │ Obsolete │─────► 移动到 archive/
    │ (已过时)  │
    └──────────┘
```

### 状态定义

| 状态 | 说明 | 目录 |
|------|------|------|
| `Draft` | 草稿阶段，可自由修改 | `active/` |
| `Proposed` | 正式提出，等待审核 | `active/` |
| `In-Review` | 进入审核流程（可评论、可修改） | `active/` |
| `Accepted` | 审核通过，准备实施 | `active/` |
| `Implemented` | 已实施并验证 | `archive/` |
| `Rejected` | 被拒绝，不实施 | `trash/` |
| `Superseded` | 被新文档取代（需标注取代者 ID） | `trash/` |
| `Obsolete` | 曾经实施但已过时 | `archive/` |

## 5. 文件命名规范

```
{TYPE}-{NNNN}_{short_title_snake_case}.md
```

- **TYPE**：文档类型（ADR/RFC/PLAN/RUN/POST/AI-NOTE/META）
- **NNNN**：四位数字，全局递增
- **short_title**：简短标题，snake_case
- 必须包含日期信息在 Front Matter 中，不在文件名里

**示例：**
- `ADR-0001_memory_layer_abstraction.md`
- `RFC-0002_mcp_server_pooling.md`
- `AI-NOTE-0003_permission_engine_review.md`

---

## 6. Front Matter 规范

每份文档必须以 YAML Front Matter 开头：

```yaml
---
id: ADR-0001
type: ADR
title: Memory Layer Abstraction
status: Implemented
author: zniverse
created: 2026-06-24
updated: 2026-06-24
reviewers: []
related: []           # 相关文档 ID 列表，如 [ADR-0002, RFC-0003]
supersedes: ~         # 取代的文档 ID（如有）
superseded_by: ~      # 被谁取代（如有）
tags: [memory, architecture]
---
```

## 7. AI 协作规范

### 7.1 AI 文档权限

| 操作 | AI 是否可执行 | 条件 |
|------|--------------|------|
| 创建 `AI-NOTE` | ✅ 自动 | 分析、审查、建议后直接创建 |
| 创建 `ADR/RFC` 草稿 | ✅ 可提议 | 需人类审批后才能进入 `Proposed` |
| 修改 `AI-NOTE` | ✅ 自动 | 仅限自己创建的 |
| 修改其他类型文档 | ❌ 禁止 | 除非人类明确授权 |
| 状态流转到 `Implemented` | ❌ 禁止 | 必须人类确认 |
| 更新 `index.md` | ✅ 自动 | 创建/移动文档后同步索引 |

### 7.2 AI 产出标记

所有 AI 创建的文档（包括 `AI-NOTE` 和 AI 起草的 `ADR/RFC`），必须在文档末尾附加：

```markdown
---
*Generated by AI Agent (agent_core)*
*Model: gpt-4o | Timestamp: 2026-06-24T21:30:00+08:00*
```

### 7.3 人机决策边界

- **AI-NOTE**：纯参考，不具约束力，人类可忽略
- **ADR/RFC Draft by AI**：是"建议稿"，人类必须 Review 后才能成为正式决策
- **人类创建的 ADR**：一经 `Accepted`，即为项目约束，代码必须遵守

## 8. 文档索引（`docs/index.md`）

`index.md` 是文档的总目录，按类型和状态分组，AI 负责在文档状态变更时自动更新。

索引格式示例：

```markdown
# Documentation Index

## ADR (Architecture Decision Records)

| ID | Title | Status | Updated |
|----|-------|--------|---------|
| ADR-0001 | Memory Layer Abstraction | Implemented | 2026-06-24 |

## RFC (Requests for Comments)

| ID | Title | Status | Updated |
|----|-------|--------|---------|
| RFC-0002 | MCP Server Pooling | In-Review | 2026-06-24 |

## AI Notes

| ID | Title | Status | Updated |
|----|-------|--------|---------|
| AI-NOTE-0003 | Permission Engine Review | Draft | 2026-06-24 |
```

## 9. 流程规则

1. **编号唯一**：`NNNN` 全局递增，删除文档也不回收编号
2. **状态变更留痕**：每次状态变更需在文档末尾添加 `## Change Log` 段落
3. **移动即状态**：文档在 `active/`、`archive/`、`trash/` 之间的移动必须伴随状态变更
4. **模板强制**：新文档必须从 `templates/` 复制模板，不得空文件创建
5. **AI 自动维护索引**：任何文档增删改后，AI 应自动更新 `index.md`
