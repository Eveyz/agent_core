## Context

`agent_core` already has an Agent Runtime that owns one model/tool loop. Custom
agent mentions and saved workflows need orchestration above that loop: explicit
dependencies, concurrency, retries, signals, timers, observation, and restart
recovery. Folding those concerns into `Run` would couple ordinary prompts to
workflow state and would make future non-agent activities difficult to add.

## Decision

Keep two runtimes with a narrow seam:

- `RunManager -> Run` remains the only path for an ordinary prompt.
- `WorkflowRuntime` owns orchestration and exposes only `start`, `command`,
  `observe`, and `recover`.
- `ActivityAdapter` is the execution boundary. The runtime schedules versioned
  activities without knowing agent internals.
- `CustomAgentActivityAdapter` invokes a shared `CustomAgentRunner`; standalone
  custom-agent execution and legacy workflow agent nodes use that same runner.
- Composer mentions and the saved-workflow canvas are authoring adapters that
  compile into the same `WorkflowSpec`.
- A run-scoped mention tool is registered only when the frontend sends a
  non-empty structured mention manifest.

## Consequences

### Positive

- Ordinary prompts do not acquire workflow tools or workflow execution state.
- New trigger and activity types can reuse the orchestration kernel.
- Custom-agent construction has one implementation for model, skills, tools,
  permissions, memory, cancellation, and history.

### Negative / Trade-offs

- The composition root must wire stores, adapters, and the runner.
- Parent Agent Runtime crash recovery remains a separate problem from workflow
  recovery.
- Cross-runtime observability needs explicit correlation rather than shared
  mutable context.

## Alternatives Considered

| Alternative | Pros | Cons | Decision |
|-------------|------|------|----------|
| Put DAG scheduling inside `Run` | Fewer top-level types | Pollutes all prompts and couples agent/tool loops to orchestration | Rejected |
| Let the parent model coordinate subagents directly | Small initial change | No durable attempts, deterministic replay, or restart recovery | Rejected |
| Separate runtime plus activity seam | Clear ownership and extensibility | Requires adapters and composition wiring | Accepted |

## Implementation Notes

- Core interface: `core/src/workflow/runtime/engine.rs`
- Activity seam: `core/src/workflow/runtime/activity.rs`
- Custom-agent adapter: `core/src/workflow/runtime/custom_agent.rs`
- Run-scoped tool injection: `core/src/runtime/run/mod.rs`
- Desktop composition root: `app/src-tauri/src/lib.rs`
- Rollback switch: set `AGENT_CORE_AGENT_MENTIONS=off` to disable mention-tool
  injection without changing ordinary prompt execution.
