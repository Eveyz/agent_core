# agent_core Documentation Convention

To keep the project documentation organized and maintainable, all team members and AI agents MUST follow these rules when creating or updating documents in the `docs/` directory.

## 1. Directory Structure

- **`docs/active_plans/`**: For currently active development plans, roadmaps, and ongoing tasks (e.g., `PLAN.md`).
- **`docs/ai_proposals/`**: For any analysis, code reviews, architectural suggestions, or product ideas generated by AI agents or human contributors that are under consideration or serve as reference. 
- **`docs/archive/`**: For completed plans, implemented designs, deprecated features, and past daily summaries. **Once a plan or task is completed, it must be moved here.**

## 2. Naming Conventions and Dates

**Dates are strictly required** for all historical, review, and proposal documents to track when the analysis or plan was made.

- **Format:** `YYYY-MM-DD_Subject_Or_Title.md`
- **Example (AI Review):** `docs/ai_proposals/2026-06-18_Code_Review.md`
- **Example (Archive):** `docs/archive/2026-06-07_TODAY_Summary.md`

*Exception:* Core active documents like `docs/active_plans/PLAN.md` that are constantly updated do not need a date in the filename, but should maintain a "Last Updated" date inside the file.

## 3. Workflow for AI Agents

Whenever an AI agent is asked to analyze the code, review PRs, or propose features:
1. **Create** the document inside `docs/ai_proposals/`.
2. **Name** the file with the current date: `YYYY-MM-DD_Topic.md`.
3. **Include** the date at the top of the markdown file as well.

Whenever an AI agent completes a plan or task listed in a document:
1. If the entire document is completed, **move** the document to `docs/archive/` and prepend the completion date to its filename if it doesn't already have one.
2. If only part of the document is completed, update the status within the active document.
